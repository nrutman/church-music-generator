# Extraction parity fixtures

## Oracle

The oracle is the two Python extractors at commit d9ec826, before their removal.
`extraction-python-golden.json` records the source SHA-256 hashes and the 96 original
Python tests executed successfully before porting. Those tests use only assertions
and `pytest.mark.parametrize`; a temporary standard-library harness expanded the
parameters and executed every case without installing pytest.

The golden corpus captures both modes independently: chord/annotation detection,
line classification, grouping at either side of the 5/15-unit thresholds,
character intervals, equidistant ties, space positions, trailing thresholds,
empty input, Unicode code points, and complete printed reports including rounding.
The results are generated by Python, not by the TypeScript implementation.

## Input fixtures

`extraction-source.pdf` is an original synthetic PDF, not a copyrighted song.
It contains “Mighty river” and “Gentle water” on two differently sized pages,
each with a leading and trailing chord. It was generated with pdf-lib's built-in
Helvetica font. `extraction-source-text.txt` is Python's complete CLI output.

`extraction-input-golden.json` contains Poppler's raw bbox XML, Tesseract's raw TSV
pages, and the words returned by the original Python input adapters. Tests parse
these frozen inputs rather than rerunning OCR and asserting version-sensitive
recognition results. They also test mocked external-tool invocation and cleanup.

## Migration validation

Before removing Python, both original and TypeScript CLIs ran on the synthetic
two-page PDF and the user-supplied “High Above All Things” PDF, using the same
local Poppler/Tesseract installations. Complete stdout was byte-for-byte identical
for both documents in both text and OCR modes. The copyrighted source and its
output are deliberately not committed.

The text CLI also runs against the synthetic PDF in CI. Missing Poppler skips
this integration case locally; CI installs Poppler. No test requires Python or
an OCR service, and no test asserts timing or fresh OCR recognition output.

## Intentional safety changes

External command failures return nonzero instead of silently accepting failed
OCR output. OCR images live in a per-run temporary directory and are removed in
a `finally` block. Tesseract receives a relative image name from that directory,
retaining the macOS path workaround without shared files in the repository root.
These changes do not alter successful extraction or mapping heuristics.

Do not regenerate oracle expectations from the implementation under test.
Any deliberate extraction changes should update focused behavioral tests and
document differences from these historical results rather than blessing snapshots.
